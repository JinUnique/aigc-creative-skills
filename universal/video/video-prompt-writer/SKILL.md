# Video Prompt Writer

把需求、完整故事或已有草稿转成能生成更好视频的提示词：故事完整可读，场景、表演、镜头与声音共同形成观众体验。最终提示词以成片表现为目标，没有简短目标；内部按任务需要规划，正文充分表达选定的视听设计。已有完整故事可独立完成；只有用户另需完整脚本、项目 bible 或协作脚本表时，才可选调用 `video-scripts-writer`，不把它设为前置依赖。

## 工作原则

- **尊重创作权限**：从零创作可补全必要设计；已有方案只补缺；局部修改锁住其余内容。用户事实、原文台词、参考职责和明确输出格式优先于默认值。
- **区分知识解释与制作设计**：写作 Agent 已知的术语无需在 skill 中重复教授；最终提示词面向视频模型，术语可直接使用，也可与具体对象、视觉特征、路径、时点、幅度和结果共同表达选定设计。后一类细节不以先有歧义或生成失败为前提。
- **主动完成视听设计**：保留已锁定故事，在可创作的场景美术、人物外观、表演、构图/焦点、镜头组织、光色与声音中作出有贡献的选择。让关键事件、人物反应和审美意图可生成、可观看；不只把故事换一种措辞，也不机械填满所有维度。
- **按成片贡献分配细节**：保留有助于美感、情绪、主体识别、空间关系、动作时序、声音和连续性的描述，不以最少字符为目标。删除重复定义、同义堆叠和过程说明；已由参考清楚承载的属性可指认其职责。视频控制确有需要的强调、关系重述和独立段锚点可以保留。
- **保留审美意图**：风格、情绪和专业术语可以是有效指令。用户要观察、氛围、建筑、抽象影像或蒙太奇时，按该形式组织，不补人物冲突、强制转折或特效奇观。
- **创作知识有适用范围**：用户或项目提供的风格指南、偏好与示例可约束本任务。区分风格不变量、可替换对象和可选技法；通用层不内置固定题材、人物、剧情或垂类依赖。中性技法短例用于说明判断，不作为通用成片模板。

## 执行流程

1. **确认目标与锁定项**。识别创作、补全或修订范围，提取主体、事件、风格、时长、画幅、语言、原文台词、参考素材及必须保留的内容。非关键缺项按当前需求补全，只有答案会改变交付方向时才询问。
2. **确认生成任务与能力**。区分生成、编辑、延长，以及叠加的图像、视频、声音和首尾帧参考。需要这些模式或具体平台时读取 [模式与平台](references/generation-modes-and-platforms.md)。素材名沿用用户提供的精确标识，不编造已上传素材或已配置的首尾帧角色。
3. **选择单片或完整故事**。`delivery_intent: single_clip | story_complete | auto`。严格单片只交付一条；完整故事保留全部关键事件，容量不足时编译连续 pack。`auto` 根据需求判断，只有单片/保全故事存在实质歧义时澄清。多段、长故事或时长超载时读取 [容量与分段](references/story-capacity-and-prompt-pack.md)。
4. **形成视听方案**。确定观众应如何理解事件、读到人物状态并感受场景，再主动设计未锁定的美术、表演、视点、镜头、光色和声音。故事任务按需读取导演/美术、叙事/表演、镜头与声音参考，完成有贡献的制作选择；重要对象、关键反应、声画关系与节奏要在正文有充分执行信息。简单片段可直接成稿；局部编辑遵从保留范围。内部 `Creative Plan` 不要求填满统一 schema，也不对外输出思考过程。
5. **组织时间与连续性**。按事件、观察过程、视点或节奏切分，不机械均分秒数或镜头数。长镜头可包含多个内部节拍。用户要求时间码、精确事件节点或连续 pack 时，按 [时间轴](references/timeline-segment-structure.md) 校验覆盖、动作完成和交接状态。
6. **渲染并检查**。按 [表达结构](references/prompt-structure-framework.md) 选择自然段、阶段/时间轴或明确的下游模板；再按 [质量检查](references/video-prompt-quality-checks.md) 检查故事、视听表现和执行正确性。需要的制作设计充分写入，发现表现不足时主动改进；不用缩短正文或自评高分代替质量判断。

## 时长与可行性

- `target_duration` 和 `segment_duration_cap` 是正数秒数；cap 是单个生成单元上限，不是故事总时长。遵从用户指定值，并核对平台最短/最长时长、离散档位与任务模式；不将 cap 限定为 15 或 30。
- 用户未指定 cap 时，选已确认能力内适合内容的值。平台未知但需要先规划完整故事时，可暂用 30 秒上限并说明仅为规划假设；不据此宣称可以原生提交。简单提示词草拟无需先完成平台选型。
- `platform_capability` 记录来源与已知范围；`generation_mode: native | extend | segment` 表示计划路径；`mode_feasibility: confirmed | conditional | blocked` 表示路径是否有能力依据。这三个判断彼此独立，未知能力不自动意味着分段。
- 动作、对白与反应放不下时，先去除非必要重复；不改变用户锁定事件。仍超载且要求严格单片时说明限制，待用户选择删改、延时或分段；完整故事任务则选择安全接点分段。执行路径未确认时保留目标与条件，不虚报支持、不静默截短。

## 交付契约

- 默认中文，遵循用户指定语言。每个可独立提交的提示词用一个代码块；诊断、来源、假设、评分和备选不写进块内。
- 简单生成可用一段话；局部编辑用“编辑目标 + 改动范围 + 保留项”；故事按场景、镜头或阶段充分组织视听信息，不要求写成短段。用户或下游明确要求标题、字段、镜头数或时间码时保留其格式。完整模板只在需要该格式时使用，不为填槽制造不适用的内容。
- 新生成内容默认不额外添加配乐或字幕；用户指定配乐/字幕时按要求设计。编辑任务以原片保留范围为准，不用默认禁令删除原有内容。纯静音只需明确一次；有混合音频来源时逐层确定由生成端、参考素材或后期负责。
- 多段 pack 在代码块外给片段清单：全局范围、本地时长、内容摘要、`continuity_in / continuity_out` 和必要素材。相邻交接摘要来自同一状态快照；普通连续交接原样复用，跳切或时间跳跃额外写 `continuity_transition`。每段正文带齐影响生成的起止状态，时间码从本地 0 开始。
- 外部说明按需出现：只有能力缺口、参考职责冲突、时长估算或其他会影响执行的条件需要说明。用户只要提示词且不存在需要说明的实质条件时，直接交付代码块。
- 不设理想字数或字数下限。沿用本项目每条 **5000 个 Unicode 字符**的默认交付上限，包含正文的空格和换行；它不是平台通则，调用方可显式调整，已确认平台更严时遵从更严限制。压缩时优先删重复与术语释义，不删故事事实、有贡献的美术/表演/镜头/声音设计、关键时序或交接锚点。
- 精确参数用阿拉伯数字与单位，如 `24mm`、`2秒`、`16:9`；时间码按目标入口支持的格式。原文台词、诗句和非精确修辞保持原文。焦段等精确参数只在有控制价值时填写。
