# 文生视频批量生产协议

当任务是文生视频批量生成、定时生成、结构化记录写入或自动化生产时使用本文件。本文件只描述批量提示词生产协议、字段、场景去重、验证和配置边界；不提供固定题材池、地点菜单、场景套餐或平台专属创意默认值。

## 1. 使用边界

适用于：

- 定时或自动化生成一条或多条文生视频提示词；
- 单次批量生成多个文生视频提示词；
- 将结构化记录、文件、接口或其他可读回载体作为主要交付面；
- 需要配置数量、主题策略、场景历史去重、字段写入和交付摘要。

边界规则：

- 已废弃的全随机定时流程不得恢复为默认生产线。
- 不从历史记录、演示数据或来源数据推断生成数量、主题、题材、地点或风格默认值；这些必须来自用户或配置。
- 数量、主题策略、目标时长、字段映射或交付面缺失且无法由调用契约确定时，停止并报告缺项，不凭空补值。
- 批量策略不得污染普通单条提示词。单条无历史任务按主技能和 `scene-design-and-diversity.md` 做本次内部候选比较与高频默认母题自检，不声称完成历史去重。
- universal 运行时只保存抽象结构、占位符与审计字段，不保存可复用的固定人物、地点、剧情、对白或 IP 模板。

## 2. 与普通单条工作流的差异

| 维度 | 普通单条 / 有参考素材 | 文生批量 |
|---|---|---|
| 素材 | 可使用参考句柄并锁定其控制职责 | 默认无参考句柄，必要静态信息在正文描述 |
| 场景设计 | 无历史时比较本次 3 个内部候选并做高频默认母题自检 | 可读取真实近期签名窗口并执行结构去重 |
| 复现 | 不要求固定 seed | 可记录 `scene_seed` 以复现候选顺序和选择过程 |
| 审计 | 内部候选、评分不输出 | 结构化记录可保存签名、锁定掩码、拒绝原因和重建次数 |
| 正文 | 默认紧凑可复制 prompt | 按字段容量写紧凑正文，不把内部审计字段塞入 prompt |
| 交付 | 聊天中的一条结果 | 批量记录、文件、接口与摘要，并执行写后读回 |

## 3. 批量配置

### 3.1 必需配置

- `generation_count`：本次接受结果的条数。
- `theme_strategy`：指定、轮换、外部规则库、人工输入或其他明确策略。
- `target_duration`：每条或各条目标时长；受当前后端真实能力约束。
- `aspect_ratio_strategy`：由发布面、主体、空间和平台要求决定。
- `delivery_surface`：结构化记录、文件、接口或其他目标载体。
- `field_mapping`：标题、日期、状态、主题、正文、约束、签名、质量记录等真实字段名。
- `dedup_window`：读取最近多少条**已接受**场景签名；若明确禁用则记录为 `0`，不能假装做了历史去重。

### 3.2 场景去重与复现配置

- `scene_seed`：可选。用于确定性复现候选生成/排序；每条可派生独立 seed。seed 不能覆盖 locked 锚点、叙事优先级或重建规则。
- `recent_scene_signatures`：调用方提供或从 `dedup_window` 读取的已接受八维签名；必须带来源标识或记录 ID。
- `scene_rebuild_threshold`：可配置。v0.8 的冷启动初值是八维 free 签名中 `>= 5` 相同触发重建；这是待真实样本校准的起点，不是永久常数。
- `max_scene_rebuilds`：调用方配置的最大重建次数。达到上限时不得静默交付碰撞稿，应记录失败或转人工复核。
- `rejection_reason_field`：保存拒绝原因代码及最小必要说明的目标字段。

历史数据只用于去重、连续性和质量反馈，不用于臆造默认主题。若无法取得可靠历史，`recent_scene_signatures` 设为空并明确 `history_dedup_applied: false`。

## 4. 每条记录的内部/结构化字段

调用方字段名可映射，但语义至少覆盖：

```text
record_id: <目标载体返回标识>
scene_seed: <可选>
locked_scene_dimensions: <dimension -> source>
scene_signature:
  spatial_topology: <normalized value>
  use_logic: <normalized value>
  access_and_power: <normalized value>
  material_system: <normalized value>
  light_logic: <normalized value>
  atmosphere: <normalized value|neutral>
  active_environment: <normalized value>
  staging_motif: <normalized value>
history_dedup_applied: <true|false>
dedup_window_used: <integer>
matched_recent_record_ids: <internal list>
same_free_dimension_count: <internal integer>
scene_rebuild_count: <integer>
scene_rejection_reasons:
  - code: <reason_code>
    matched_record_id: <optional>
    changed_free_dimensions: <internal list>
quality_status: <accepted|rejected|needs_review>
```

这些字段是批量审计面，不进入复制用提示词。历史签名保存抽象值，不保存可直接复制的成片场景句子。

## 5. 主题与内容策略

主题、内容线、人物、场景锚点、禁区和连续性应来自外部配置、用户输入、项目规则或被明确授权的记录字段。本文件只使用跨题材抽象判据：

- 是否有清楚的可见事件、关系变化或状态变化；
- 是否能在目标时长内完成必要节拍，并留出反应和结尾余波；
- 是否能由画面、表演和声音呈现，而不是依赖字幕解释；
- 是否避开事实、版权、平台和用户禁区；
- 与近期输出的差异是否改变场景结构、镜头控制、动作机制、视效因果、声音关系或结尾功能，而不只是换名词。

## 6. 场景候选、签名与去重

场景设计完整规则见 `scene-design-and-diversity.md`。批量模式必须按以下顺序执行。

### 6.1 锁定场景维度

1. 从当前 brief、外部配置、参考素材（若工作流明确允许）和续写连续性提取场景锚点。
2. 明确提供的维度标记为 `locked`，记录来源；其余为 `free`。
3. locked 进入所有候选，不计入新颖性惩罚，去重或 seed 均不得覆盖。
4. 连续批次若要求复用场景，应在签名比较前把有连续性证据且确有必要复用的维度标为 locked 并排除碰撞计数；无法指出证据的维度保持 free，不得事后改标以规避碰撞。

### 6.2 内部生成 3 个候选

- 每条结果内部生成 3 个 ScenePlan 候选，不向最终用户或 prompt 暴露。
- 三个候选保持同一叙事功能和核心事件；候选间至少 3 个 free 维度产生实质控制差异。
- 候选按 `叙事相关性 > 可生成性 > 连续性 > 新颖性` 选择；新颖性只作同分项，不能抵消叙事或 locked 失败。
- `scene_seed` 只固定候选过程的可复现顺序，不把候选变成随机地点抽签。
- 没有可靠历史时，除三候选结构差异外还要做高频默认母题自检；若全部候选受 brief 未支持的高显著性默认先验主导，从 `narrative_function → spatial_topology` 重推至少一个。不得使用地点、天气、时段、配色黑名单或具体组合包实现该自检。

### 6.3 建立八维签名

每个候选归一化为：

```text
spatial_topology
use_logic
access_and_power
material_system
light_logic
atmosphere
active_environment
staging_motif
```

地点、修辞和同义词变化不进入签名差异。结构不变时，即使正文名词不同也视为同一值。

### 6.4 比较近期窗口

对候选与 `recent_scene_signatures` 中每个已接受结果比较：

1. 比较前先完成有证据的连续性 locked 标记；仅计算当前候选仍为 free 的维度，locked 维度不计相同数。
2. 只有候选与所有历史结果的 free 相同数都低于当前 `scene_rebuild_threshold`，才通过新颖性门槛；若任一历史结果达到阈值，拒绝候选并记录 `SIGNATURE_COLLISION`。
3. v0.8 初值为“八维 free 签名中 5 个或以上相同”，必须可配置并基于真实批量样本校准。
4. 若因 locked 导致可比较 free 维度少于当前阈值，不自动降低阈值，不改 locked，碰撞条件自然不可达；候选仍须通过三候选差异、连续性及其余硬门槛。
5. 没有历史签名时记录 `history_dedup_applied: false`；执行候选间比较与高频默认母题自检，不生成伪造的历史匹配 ID 或重复率。
6. 连续性只保护比较前已锁定且有证据的维度，不构成接受 free 碰撞的例外；free 仍碰撞且达到 `max_scene_rebuilds` 时只能标记 `needs_review` 或 `rejected`。

### 6.5 失败重建

触发签名碰撞后：

1. 回到最早重复的 free 逻辑层，不在成句上替换名词。
2. 至少改变 3 个未锁定维度，再完整推导其下游材质、光线、环境和连续性影响。
3. 每项变化必须改变叙事意义或生成控制；随机换地点、天气、时段或材质名但结构控制不变，记录 `LEXICAL_ONLY_CHANGE` 或 `RANDOM_LOCATION_SWAP` 并继续重建。
4. 每轮记录拒绝代码、匹配记录、相同维度数和实际改变的 free 维度。
5. 每轮都重新检查 locked、叙事相关性、可生成性、连续性和签名，不只重新算新颖性。
6. 达到 `max_scene_rebuilds` 后 free 维度仍碰撞或仍无可接受候选时，标记 `needs_review` 或 `rejected`，不得以连续性为例外、静默放宽 locked、伪造签名或把碰撞稿写为 accepted。

常用抽象拒绝代码：

- `LOCKED_CONFLICT`
- `NARRATIVE_MISMATCH`
- `GENERATABILITY_OVERLOAD`
- `CONTINUITY_BREAK`
- `SIGNATURE_COLLISION`
- `LEXICAL_ONLY_CHANGE`
- `RANDOM_LOCATION_SWAP`
- `TERM_OR_EFFECT_CONFLICT`

## 7. 文生提示词正文规则

每条提示词遵循主技能输出契约，并满足：

- 不写参考职责段，不使用未配置的 `@参考` 句柄。
- `【基础设定】` 写清当前生成必要的主体、关系、ScenePlan 结果和 locked 连续性，不输出候选或签名。
- `【氛围与画质】` 只选择少量准确术语，并绑定光线、空间、材质、运动或声音的可观察效果；术语体系见 `video-element-knowledge-base.md`。
- `【画面内容】` 按主模板字段组织，每个时间片写清镜头、行动、视效/自然变化、声音与转折。
- 光线有来源、方向、光质、遮挡和变化逻辑；材质有反射、粗糙度、接触或磨损结果；环境运动有动力来源、路径、交互与残留。
- 低视效场景保留真实物理/光学变化，不为差异化强加奇观。
- 声音写声源、材质、空间、时间和层级；未被要求时不添加配乐。
- 必要约束才输出；无内容的约束区不为了模板占位而写“无”。
- 不设固定字数下限。按目标时长、后端输入上限和不可替代信息控制篇幅，优先删除字段内容中的重复锚点、泛化质量词与冲突修饰；每个时间片仍保留七字段标签和固定顺序。
- 复制用正文不得包含 seed、配置、评分、签名、候选、拒绝原因、来源分析或交付摘要。

## 8. 结构化记录与 Prompt Payload 边界

批量任务的数据库记录、摘要列或检索字段可以把信息组织成自然连续段落；但凡字段值将作为可粘贴 Prompt Payload 交付，就必须保留每个时间片的七字段标签和固定顺序。结构化记录仍应能追溯：

- 时间范围与本段主要变化；
- 景别/机位、摄影机是否移动及其叙事动机；
- 主体行动、表演、空间关系和前后连续性；
- 视效或自然物理变化的来源、路径、交互和残留；
- 声音/对白的声源、时间、层级和收尾；
- 结束状态如何推进或回答本段叙事问题。

批量字段统一按主模板结构写入，保证可读、可查、可复核。

## 9. 批量执行流程

1. **读取配置**：数量、主题策略、时长、画幅、交付面、字段映射、`dedup_window`、可选 seed、阈值与最大重建次数。
2. **读取历史**：只读近期已接受签名和明确连续性；验证来源与字段完整性。取不到时显式关闭历史去重声明。
3. **分配条目上下文**：为每条建立 brief、locked/free 场景锚点与可选派生 seed。
4. **生成内部候选**：每条 3 个 ScenePlan；按相关性、可生成性、连续性、新颖性选候选；无可靠历史时额外执行高频默认母题自检。
5. **签名比较与重建**：对近期窗口和本批次已接受结果去重；碰撞时至少重建 3 个 free 维度并记录原因。
6. **写提示词**：渲染被选 ScenePlan，使用少量绑定可见效果的专业术语；审计信息不进入 prompt。
7. **本地校验**：检查数量、字段、时间覆盖、locked、签名、约束、无参考句柄、无内部记录污染和信息密度。
8. **写入目标**：遵守真实字段选项、只读字段和授权范围。
9. **读回验证**：使用写入返回的记录 ID、路径或接口回执读回，不通过标题搜索猜测成功。
10. **更新窗口**：仅把读回验证通过且状态为 accepted 的签名加入后续比较；拒绝稿只进入审计。
11. **交付摘要**：报告配置结果、位置、数量、接受/拒绝/复核状态和真实问题；用户未要求时不粘贴完整批量正文。

## 10. 验收

每条及整批至少检查：

- 数量、主题、时长、画幅、交付面和字段映射来自真实配置。
- 场景锚点按 brief、参考素材和连续性正确标记 locked/free；新颖性没有覆盖 locked。
- 每条内部生成 3 个候选，最终 prompt 不泄露候选、评分、签名或拒绝原因。
- ScenePlan 从叙事功能推到空间、使用/权力、材质/光线、环境运动和视觉表面，不从地点名反推。
- 八维签名完整；窗口只含真实 accepted 历史和本批次已接受记录。
- `>=5/8` free 维度相同重建是可配置、待校准初值，不是硬编码永久真理。
- 连续性必要维度在比较前 locked 并排除碰撞计数；只有 free 相同数低于阈值才接受，free 仍碰撞且达到上限时只能复核或拒绝。
- 碰撞重建至少改变 3 个 free 维度；词面变化但结构相同仍被拒绝。
- 无可靠历史时除三候选差异外已执行高频默认母题自检，且未使用地点、天气、时段、配色黑名单或具体组合包。
- 场景差异改变叙事意义或生成控制，没有随机换地点破坏连续性。
- 每条在空间、镜头、动作、视效因果、声音或结尾功能上有必要差异，同时保持各自 brief 的相关性。
- 专业术语少量、准确、可观察、兼容；没有“电影感 / 高级感 / 8K”填充或术语堆砌。
- 光影、构图、材质、空间、物理因果、制作细节没有因去场景词库而下降。
- 写入后以返回标识读回；完整 prompt、签名、状态和拒绝记录与本地结果一致。
- 文件和输出都不包含固定场景包、地点清单、天气+时段+材质套餐、固定异常反差、题材/IP/固定人物/固定剧情语料。

## 11. 常见失败

1. 把历史记录当主题默认池，而不是去重与连续性证据。
2. 只改地点名、天气词或材质名，八维结构完全相同。
3. 为避免重复而改动 locked 地理、光线或动作接点。
4. seed 固定后跳过三候选、相关性排序或碰撞重建。
5. 没有历史却填写匹配记录或声称“最近结果已去重”。
6. 重建只做词面补丁，没有改变至少 3 个 free 控制维度。
7. 把签名、评分或拒绝原因写进复制用 prompt。
8. 为差异化增加不必要主体、场景切换、VFX 或声音层，导致时长过载。
9. 用术语数量、固定字数或模板标签数量代替可生成质量。
10. 写入后不按返回 ID/路径读回，只凭标题或请求成功码推断完成。
