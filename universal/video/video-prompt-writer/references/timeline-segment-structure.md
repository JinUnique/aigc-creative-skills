# 时间片分段结构

本文件定义 1–30 秒单叙事单元的时间轴槽位、事件驱动切分、连续覆盖与长镜头组织，也给出完整故事超出单段容量时的处理顺序。它只提供抽象规则与占位符，不提供固定题材或剧情样本。完整故事的意图路由、分段边界、continuity ledger 与多段验收见 `story-capacity-and-prompt-pack.md`；本文件只处理单个 Prompt Payload 内部的时间轴。

## 内部时间片槽位

Creative Plan 中每个时间片至少校验：

```text
start_time / end_time
primary_change
shot_view_and_motivation
camera_behavior
visible_action_and_space
visual_or_physical_change_if_relevant
audio_timing_role
state_transition
continuity_in / continuity_out
```

这些内部槽位按主模板字段落地：`时间段`、`景别/镜头`、`运镜`、`画面内容`、`视效/VFX`、`声音/对白`、`情绪转折`。内部槽位用于校验完整度，主模板字段用于最终输出；默认输出形态见文末。

## 切分原则：事件与状态优先

新建时间片的信号包括：

- 主要行动进入准备、启动、接触、反应或恢复的新阶段；
- 观众获得新信息，或信息被有意隐藏；
- 主体距离、高低、前后景、入口/出口、遮挡或行动面发生变化；
- 视点、焦点、景别或摄影机行为需要承担新的叙事功能；
- 环境声、事件音、人声、静默或余波开始承担新职责；
- 物理/光学变化进入来源、扩展、交互、峰值或衰减阶段；
- 可观察的关系、情绪或权力状态发生变化。

必须按事件/状态变化切分，**不机械均分**。同一变化需要更多完成时间就给更长时间片；简单反应可以更短。每片只保留一个主要变化，次级细节服务该变化。

## 时长档位与软预算

### 1–2 秒：极短落点

- 一个动作点、接触点、反应点或状态变化；
- 通常一个节拍、一个镜头；
- 不加入解释性前史、连续对白或多步因果链。

### 1–8 秒 micro（重点覆盖 3–8 秒）

- 3–8 秒通常 1–3 个节拍、1–2 个镜头；
- 围绕一个核心动作、揭示或关系变化；
- 先保证动作起止和可辨识结果，再增加镜头变化；
- 对白如有，只使用实际可用说话时间，并给动作/反应留空间。

### 9–15 秒 short

- 通常 2–4 个节拍、1–4 个镜头；
- 可容纳建立、变化和余波，但仍聚焦一个核心时刻；
- 镜头切换必须新增信息、关系、视点或节奏，不为凑数量切镜；
- 结尾不再引入新的主要事件。

### 16–30 秒 extended

- 一个完整叙事单元，通常 4–7 个节拍、1–7 个逻辑相连镜头；
- 可以有建立、发展、转折和收束，也可以保持单一连续长镜头；
- 所有节拍共享同一因果链、关系问题、空间推进或目标变化；
- 不自动增加场景、角色、对白、特效或支线，不组织无关蒙太奇；
- 为动作完成、反应、停顿、环境和最后画面功能预留真实时间。

以上都是软预算。内容简单时允许更少，复杂 brief 超载时先删减而非突破可实现性。

## 连续长镜头

连续长镜头允许少镜头、多节拍，不受镜头数建议下限约束。内部可由以下节点组织：

- 人物行动路径或速度改变；
- 前景遮挡与重新显露；
- 焦点在主体、物件或空间线索间转移；
- 人物距离、高低、身体朝向或权力位置改变；
- 环境运动、光线、声音或表演状态改变；
- 摄影机跟随、停看、重构或改变距离，并有叙事动机。

不得把连续长镜头写成静态拖长，也不得为了满足节拍预算强制切镜。

## 时间码连续覆盖规则

每条时间轴必须满足：

1. 第一片从 `0` 开始，最后一片结束于 target_duration。
2. 当前片 `end_time` 等于下一片 `start_time`。
3. 时间片不重叠、不倒序，也没有未解释空洞。
4. 所有时间码连续且完整覆盖目标时长。
5. 单个时间片有足够时间完成其主要动作、反应或对白。
6. 结尾保留可辨识动作落点、关系结果、声音余波或稳定构图，不在最后瞬间堆新事件。

最后余量按内容决定，可将总时长约 5%–10% 作为初始观察值，但不能机械套用固定秒数。

## 容量决策顺序

1. 锁定不可删除项：身份/素材锚点、核心行动、关键转折、必要对白、目标时长和硬约束。
2. 估算每个动作真实完成时间，包括准备、路径、接触、反应和恢复。
3. 预留停顿、环境、观众识别和最后状态时间。
4. 按事件变化确定边界，再选择镜头数量；不先均分秒数。
5. 超载时先删次要镜头、重复形容、重复信息、装饰性视觉变化与解释性台词。
6. 仍超载时：`single_clip` 标记 blocked 并请求授权；`story_complete` 按 `story-capacity-and-prompt-pack.md` 编译 StoryPromptPack。不得加速全部动作与台词来硬塞。

## 平台能力与时长实现

内部同时记录：

```text
target_duration: <1–30 秒>
platform_capability: <known profile / unknown>
generation_mode: native | extend | segment
mode_feasibility: confirmed | conditional | blocked
```

- 目标后端明确原生覆盖 target_duration 才用 `native`。
- 原生上限不足、但可延长同一叙事单元时用 `extend`，把 continuity_out 传给下一阶段。
- 已知执行流程要求分段或容量明确超载时用 `segment`，保留 master timeline 和每段 continuity_in/out。
- 能力未知不自动推出任何 generation mode。计划模式必须来自用户偏好、已知工具链、连续性需要或容量判断，并标记 `mode_feasibility: conditional`；若执行路径未确认，只给条件式方案并在提交前核验。
- skill 能规划 30 秒不等于后端原生支持 30 秒；未知时不得虚报原生、延长或分段能力，也不得静默截短。

## 视觉、声音与对白

### 视觉/物理变化

只在相关时规划视觉或物理变化：说明来源、路径、与主体/环境交互、强度与余波。极简现实片段不强行添加人工 VFX，也不要求可见 `视效/VFX：` 占位；自然变化可融合进动作和空间句。

### 声音

先确定 `audio_policy: generated_audio | external_track | silent`。正常音频写清环境底层是否连续、拟音/事件音绑定何种动作和材质、人声远近与可懂度，以及声音桥或余波如何承接。外部成曲且生成端静音时，每片写与已提供音轨/歌词段的同步职责；没有音频分析证据时不得声称鼓点、BPM 或精确拍点。纯静音任务每片写静默与可见动作、停顿或构图节奏的关系。三类职责都要落在对应时间片的 `声音/对白` 字段，不能只在全局写一句声音约束。

### 对白收尾余量

对白预算基于可用说话时间，而非总时长；先把独立非语言节点归入保留时间，再对完整台词交付实测：

```text
reserved_nonverbal_time = 独立于台词交付的必要动作 / 反应 / 环境节点 / 声音桥独占节点 / 结尾余波
usable_speech_time = 时间片时长 - reserved_nonverbal_time
sum(measured_delivery_duration_per_exchange) <= usable_speech_time
```

- 每轮 `measured_delivery_duration` 已包含交付内呼吸、句内停顿、response gap、重叠和打断；这些成分不得再进入 `reserved_nonverbal_time` 或二次扣除；
- 首稿可以保守估算，最终以真人朗读或目标 TTS 的完整交付实测为准；未实测只能标记估算，不能声称已验证；
- 台词必须在所属时间片结束前完成；
- 片段尾部留给表情、动作、环境声、呼吸或稳定构图；
- 若说不完，先删解释性台词或缩短句子，仍超载则拆分，不把人声顶到最终时间码。

## 输出形态

`【画面内容】` 默认按主模板字段逐项输出，不使用省略标签的压缩形态：

```text
时间段：...
景别/镜头：...
运镜：...
画面内容：...
视效/VFX：...
声音/对白：...
情绪转折：...
```

批量结构化写入时，数据库记录、摘要列或检索字段可以融合成自然段；任何将作为可粘贴 Prompt Payload 的字段始终保留主模板七字段和固定顺序，保证可读、可查、可复核。
