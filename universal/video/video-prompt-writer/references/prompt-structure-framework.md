# 视频提示词结构框架

本文件定义单叙事单元视频提示词的两层架构：内部 **Creative Plan** 用于规划与校验，外部 **Prompt Payload** 用于交付。只提供抽象结构、占位符、渲染规则和压缩顺序，不提供固定人物、场景、对白或剧情样本。

## 总公式

```text
交付 = 可选外部诊断 + 一个复制用 Prompt Payload 或一个 StoryPromptPack（含 N 个独立 Prompt Payload）
内部质量控制 = Creative Plan + 时间轴/能力/约束审计
```

内部结构完整不意味着把 schema 键写入最终 prompt。全局标题和时间码承担阅读与时序控制；每条 Prompt Payload 内，时间片字段标签是 v0.7.2 起的显式输出契约，必须按固定顺序保留，压缩发生在字段内容内部，不删除标签。完整故事超出单段容量时，按 `story-capacity-and-prompt-pack.md` 编译 StoryPromptPack；本文件其余规则对 pack 中的每条 payload 同样适用。

## Internal Creative Plan

生成正文前至少完成以下规划槽位：

```text
Creative Plan
  task_mode
  target_duration
  platform_capability
  generation_mode
  mode_feasibility
  global_anchors
  scene_plan
  beats
  dialogue_plan
  directorial_plan
  shot_and_timeline_plan
  sound
  constraints
  quality_audit
```

### 槽位职责

- `task_mode`：文生、图生、多参考、首尾帧、编辑、延长或融合。
- `target_duration`：1–30 秒目标时长及其软预算档位。
- `platform_capability`：目标后端已知原生时长上限、延长/分段能力、输入承载和资料来源；未知时明确为 `unknown`。
- `generation_mode`：`native | extend | segment`，记录计划的执行策略，不由 capability 状态直接推导。
- `mode_feasibility`：`confirmed | conditional | blocked`。只有能力资料与执行路径都支持计划模式时才是 `confirmed`；能力未知或路径待核验时为 `conditional`。
- `global_anchors`：主体身份、参考素材职责、空间、光线、材质、动作方向、首尾状态及不可变连续性。
- `scene_plan`：服务叙事功能的空间与活动逻辑，不从固定具体场景包抽取。
- `beats`：按事件、关系、视点、声音职责或状态变化组织的节拍。
- `dialogue_plan`：说话者、目的、可用说话时间、停顿、结束点和尾部余量；无对白时保持空计划而非制造台词。
- `directorial_plan`：观众信息、情绪曲线、blocking、揭示/隐藏、摄影机动机和最后画面功能。
- `shot_and_timeline_plan`：时间片、景别/机位/焦点/运动、连续长镜头内部节点与连续性。
- `sound`：先记录 `audio_policy: generated_audio | external_track | silent`，再记录环境底层、拟音/事件音、人声、声音桥、外部音轨同步或静默/余波及混音层级；外部音轨未提供可核验节拍时不得制造精确拍点。
- `constraints`：声音与画面硬约束、平台限制、素材不可变内容及冲突解决。
- `quality_audit`：时长覆盖、字段完整、可实现性、冲突和信息密度。

Creative Plan 默认不展示，不要求程序化 JSON，也不进入复制代码块。

## 能力路由与外部诊断

“prompt 能描述 30 秒”与“后端能原生生成 30 秒”是两个判断：

```text
platform_capability: <已知能力与来源 / unknown>
generation_mode: native | extend | segment
mode_feasibility: confirmed | conditional | blocked
routing_note: <能力低于目标或未知时，说明延长/分段与连续性传递；不得静默截短>
```

- 已知原生覆盖目标时长：`native`。
- 已知原生上限较短且支持延长：`extend`，传递 global anchors、动作方向、空间、光线、声音和接点状态。
- 已知执行流程要求分段，或容量检查明确需要拆分：`segment`，保留 target-duration master plan 与 continuity in/out。
- 能力未知本身不决定 `generation_mode`。若用户偏好、已知工具链或连续性/容量判断给出计划模式，记录该模式并标记 `mode_feasibility: conditional`；若没有路径得到确认，只在 routing note 给出条件式方案并要求执行前确认。
- 能力未知不能写“原生支持”“支持延长”或“支持分段”，也不能把 30 秒 prompt 静默改成较短时长。

诊断服务于人或执行系统，不进入 Prompt Payload。


## 复制用正文骨架（主模板）

### 1. `【基础设定】`

负责回答“画面里有什么实体和空间”。必须包含：

- 角色设定：身份/职业/物种、数量/年龄/性别、体态轮廓、时代/美术风格；性格状态/行为属性；面部/五官/表情/神态；服装/配饰/道具/装备；颜色/材质/质感/破损/限制；需要连续保持的 `@素材名`。
- 群体角色：仅用于完全不参与互动的纯背景人群；若有台词、被招呼、对视、反应或互动，即使是次要主体也按完整角色写。
- 场景设定：年代/地域/空间类型、事件背景、季节/天气/时间/光照、建筑/自然/室内元素、大型与小型道具、秩序或破坏程度、地面/墙面/空气/远景/近景、日常元素与异常元素的反差。

### 2. `【氛围与画质】`

负责回答“这个世界以怎样的影像容器被拍出来”。必须包含：

- 风格核心：题材类型、真实感等级、影像质感、媒介模拟和需要避免的质感偏差。
- 反差关系：正常/危险、日常/异常、温暖/冷清、秩序/失控等可被画面支持的关系。
- 动态与动作：速度、冲击力、流畅度、运动感和需要避免的动作问题。
- 情绪基调：用影像与声音可支持的氛围词，不只写抽象感受。
- 摄影语言：画幅、摄影机质感、镜头风格、景深、动态模糊、手持感、长焦压缩或广角透视。
- 色彩与影调：主色关系、饱和度、对比度、颗粒、锐度、柔光或高锐度质感。
- 光照设计：光源类型、方向、光质、明暗过渡、暗部细节、高光控制和叙事功能。

### 3. `【画面内容】`

负责回答“事件如何按时间发生”。每个分镜至少包含：

```text
时间段：<开始时间>-<结束时间>
景别/镜头：<景别、拍摄方向、机位高度、角度、构图方式、主体位置、环境/背景位置、空间层次、焦点优先级与本镜头叙事功能>
运镜：<运动方式、节奏、是否跟随主体、焦点转移、固定/摇/推拉/升降>
画面内容：主体、动作、表情、服装/道具、空间关系、环境细节、光线、色彩、材质、前中后景与可见因果。
视效/VFX：可见视效或物理变化的现象、位置、路径、运动、强度变化、与主体/镜头/环境的交互；无明显视效时写“无人工视效，仅保留真实自然变化：...”。
声音/对白：环境声、动作声、音乐、对白、语气、停顿；不写视觉特效。
情绪转折：<开始状态> -> <结束状态>
```

`画面内容` 是实体与空间字段，必须写主体、环境、构图、动作、空间关系、可见状态和细节变化，不把故事梗概塞进一句剧情总结。每个时间片至少选择 4-6 个适用的具体项落地：主体姿态/动作、表情细节、手部/物件互动、服装/材质、道具状态、空间调度、前景/中景/背景、光线方向、表面纹理、色彩对比、环境运动、与上一镜连续性。

`视效/VFX` 是可见变化字段，包含光效、粒子、能量、烟雾、水火、电弧、变形、材质变化、镜头污染、合成层、转场特效；没有人工特效时，也写真实光影或物理变化，如反光、尘埃、呼吸白雾、雨水、烟气、曝光或实际灯光变化。强视效写来源、扩展路径、接触/冲击、遮挡/反射、峰值、衰减/残留和连续性；现实低效场景不要强行奇观化。

`声音/对白` 只写音频：环境声、动作声、音乐、对白、语气、停顿。不要把视觉特效、光效路径、材质变形或镜头污染写进声音字段。

### 4. `【声音约束】`

负责把声音从“情绪形容词”变成可生成的声源、材质、空间和时间关系。必须写清：

- 环境底层是否跨镜连续；
- 拟音、事件音、身体声、物件声和物理/视效声的来源与材质；
- 声音桥、静默、余波和混音层级；
- 人声/画外音归属、距离、音量、可懂度和收尾余量；
- 默认 `禁止BGM/配乐`。

### 5. `【画面约束】`

默认固定为：

```text
禁止任何字幕。
```

额外画面限制只写与当前任务相关的身份稳定、文字、主体数量、品牌标识、剪辑稳定性或平台约束；不要把声音限制塞进画面约束。

## 连续性规则

多分镜片段必须显式保持：

- 主体身份、服装、道具、身体状态和位置连续；
- 场景方向、前中背景、光源、行动面和遮挡关系连续；
- 动作准备、路径、接触、反应和恢复能接上；
- 声音底层、事件音余波、静默或人声收尾能跨镜承接；
- 情绪从上一镜结束状态推进到下一镜开始状态。


## 时间与信息软预算

先按真实完成时间分配行动、反应、停顿、环境和结尾余量，再决定文字密度：

- `1–8 秒`：一个核心变化；其中 3–8 秒通常 1–3 个节拍、1–2 个镜头；
- `9–15 秒`：建立、变化与余波，通常 2–4 个节拍、1–4 个镜头；
- `16–30 秒`：一个完整叙事单元，通常 4–7 个节拍、1–7 个逻辑相连镜头。

连续长镜头允许一个镜头承载多个内部节拍。镜头和节拍数量都是软预算，不得机械补齐。信息预算受后端承载优先约束；1–8、9–15、16–30 秒可分别观察约 450–1000、700–1800、1200–3000 个中文字符，但这些不是硬下限、硬上限或交付门禁。

## 压缩顺序

压缩只发生在单条 Prompt Payload 内部，且不得删除时间片字段标签或整体字段；pack 之间的重复锚点是独立生成所需，不在压缩范围。

1. 删除不服务叙事、动作或平台能力的装饰性镜头/VFX/声音。
2. 删除重复的全局设定、同义形容词、无法观察的修饰词与诊断解释。
3. 删除可被画面完整替代的解释性台词。
4. 合并同一时间片内重复的约束与噪声词，保留字段顺序与实体内容。
5. 最后才压缩主体身份、关键因果、逐片景别、摄影机行为与动机、时间顺序、连续性、音频时序职责与硬约束；这些槽位只可改写得更短，不可删除。

无固定字数下限。不得把长度当质量代理，也不得为达到字符数制造角色细节、场景、对白、VFX 或约束。
