# 台词节奏、时长预算与画外音

本文件负责单片段视频提示词中的可用说话时间、语速校准、真人朗读 / 目标 TTS 验证、停顿与重叠计时、画外音归属和人声可懂度。对白的欲望、策略、潜台词、权力变化、角色声线与删改测试由 `narrative-script-performance-direction.md` 负责；环境声、拟音、声音桥和混音层级由 `sound-design-foley-ambient-mix.md` 负责。

这里只提供可校准的起始区间和验证流程，不提供固定台词、固定人物、固定剧情或把理论容量伪装成实测结果。

---

## 一、先留表演时间，再算台词预算

总时长不是全部可说话时间。叙事视频默认要让独立动作、无台词反应、环境、声音桥独占节点与最后余波真实发生，不能先写满台词再压缩表演。呼吸、句内停顿、response gap、重叠和打断属于台词交付本身，进入逐轮完整交付实测，不放进独立非语言保留时间。

### 1.1 核心公式

```text
reserved_nonverbal_time
  = 开场建立
  + 独立于台词交付的必要动作与接触
  + 独立于台词交付的无台词反应
  + 环境或声音桥独占节点
  + 结尾动作 / 静默 / 余波

usable_speech_time
  = duration - reserved_nonverbal_time

draft_dialogue_chars
  = usable_speech_time × drafting_rate_estimate

sum(measured_delivery_duration_per_exchange)
  <= usable_speech_time
```

- `duration`：目标片段总时长。
- `reserved_nonverbal_time`：只保留给独立于台词交付的非语言内容；与台词并行的表演不重复占槽，呼吸、句内停顿、response gap、重叠和打断也不列入这里。
- `drafting_rate_estimate`：只用于第一次起草的保守字符容量估算，不是完成度证明，也不是最终时长依据。
- `measured_delivery_duration_per_exchange`：真人朗读或目标 TTS 下，该轮从交付准备到交接结束的完整实测时长，已包含呼吸、句内停顿、response gap、重叠与打断。
- 最终验证只比较逐轮 `measured_delivery_duration` 总和与 `usable_speech_time`。上述交付成分既然已经实测，绝不再从 `usable_speech_time` 二次扣除。
- 未做真人朗读或目标 TTS 时，只能使用起草估算并标记 `unverified_estimate`，不能声称台词已通过时长验证。

叙事视频默认至少为独立非语言动作、反应、环境和结尾留出约 30% 总时长；复杂独立动作或声音桥独占节点较多时应留更多。纯口播、明确的快速播报或用户锁定的语言主导形式可以例外，但呼吸和发音起落仍须进入完整 delivery 实测，结束余量仍须保留。

### 1.2 保留时间的分配顺序

1. 锁定不可压缩的动作、接触、信息反应和最后画面。
2. 标出独立于任何台词交付的观察、动作与无台词反应；同时发生的表演只写进时间轴，不重复保留。
3. 在各 exchange 内标出吸气、`pause`、response gap、`overlap`、`interrupt` 以及被动作 / 声音切断的节点，留待完整交付实测。
4. 标出跨镜声音桥是否占用听觉前景；前景桥存在时，不同时塞入另一条关键信息。
5. 为最后一句之后保留反应、收声、余音或稳定画面。
6. 可用 `usable_speech_time` 估算首稿字数；成稿必须改用逐轮完整交付实测总和验收，绝不二次扣时，也不反过来删掉必要表演。

## 二、中文语速：起始校准带，不是理论上限

语言、发音清晰度、词汇难度、情绪、口型、气息和目标 TTS 都会改变实际语速。下表只用于第一次草拟字符量；最终以当前台词包含完整 delivery 的逐轮实测为准，不再另扣停顿或呼吸。

| 语速档 | 起始参考字 / 秒 | 使用条件 |
|---|---:|---|
| 克制 / 留白 | 2.5–3.5 | 反应、低声、复杂情绪、句间留白或需要看清表演 |
| 自然对话 | 3.5–5 | 大多数叙事对白的默认起点，包含自然换气与短停顿 |
| 利落 / 明确加速 | 5–6.5 | 目标清楚、句法较短、发音可懂；必须朗读或 TTS 校时 |
| 实验性极短爆发 | 7–9 | 只可用于极短抢话、喊叫、rap、列表式爆发或刻意失控；不可标为普通快语速，必须实测 |

纪律：

- 普通“快语速”不得使用 `7–9 字 / 秒` 作为预算区间。
- `7–9 字 / 秒` 不是整段容量，也不应跨多句持续；爆发前后的吸气、反应和可懂度仍占时间。
- 情绪强烈不等于语速更快。克制、恐惧、犹豫、压迫或权力计算常使停顿变长。
- 专有词、数字、外语、复杂修饰、绕口音节和情绪破裂通常比同字数的常用短句更慢。
- 角色声线决定句长、直接程度和节奏；不能为满足理论字数而把所有角色统一成同一种快嘴。

## 三、逐轮计时，而不是只算总字数

多人对白应按 exchange 逐轮估时，再放回同一时间轴。总字数合格不代表每轮节奏可演。

```text
ExchangeTiming
  speaker: <说话者>
  spoken_text: <实际台词>
  delivery_start_end: <该轮从交付准备到交接结束的时间轴起止>
  articulation_span: <实测发音段，仅作诊断，不单独用于最终预算>
  breath_and_internal_pause: <交付内呼吸与句内功能性停顿>
  response_gap: <归属本轮、且只计一次的接收与反应间隔>
  overlap_or_interruption: <与谁重叠或被何者打断、哪句必须听清>
  measured_delivery_duration: <完整实测交付时长，包含以上 delivery 成分>
  independent_nonverbal_after: <若有，属于 reserved_nonverbal_time 的独立动作 / 反应 / 环境节点>
```

### 3.1 停顿

停顿必须有戏剧功能并占时间：

- 让信息被理解或让反应成为前景；
- 迫使对方补充、退让或暴露；
- 保护 withheld 信息；
- 显示人物在改换 tactic；
- 让环境、物件或声音桥接管注意力。

不要用统一的固定秒数替代实测。明显停顿在朗读 / TTS 中保留，并把停顿期间可见的视线、呼吸、手部、位置或环境变化写进时间轴；该停顿只进入对应轮次的 `measured_delivery_duration`，不再进入 `reserved_nonverbal_time`。

### 3.2 重叠与抢话

- 两人同时说话不会让观众的理解容量翻倍。
- 重叠只用于争夺话语权、协作抢拍、遮住信息、误听或策略变化。
- 明确前景句、背景句和必须听清的关键词；若两条都必须完整理解，就不要重叠。
- 计时按真实时间轴记录，并把参与重叠的交付写入对应轮次的 `measured_delivery_duration`；质量审计同时按听觉前景的信息负载检查。重叠不进入 `reserved_nonverbal_time`，也不能在总和比较后再次扣除。
- 三人以上场景默认降低语言密度，一次只推进一个主交流结果。

### 3.3 打断

打断点要落在可表演位置，并产生 `local_outcome`：改变谁控制时间、谁被迫换策略、哪项信息被释放或继续 withheld。若打断后什么都没变，它只是噪音，应删除。

## 四、真人朗读 / 目标 TTS 验证流程

“看起来不长”不是验证。完成台词草稿后执行：

1. **准备可读稿**：只保留真正会说出的文字；把表演指令移出朗读文本，但保留需发声的呼吸、犹豫和截断。
2. **按角色声线朗读**：使用目标直接程度、情绪压力、句长、停顿、重叠和打断，不用播音式匀速代替角色表演。
3. **记录实测**：记录每轮从交付准备到交接结束的 `measured_delivery_duration`，完整包含呼吸、句内停顿、response gap、重叠和打断；articulation 与时间轴只作诊断。
4. **优先目标 TTS**：若交付后端会使用特定 TTS / 视频模型人声，使用同一文本、语言、voice 和速率参数实测；不能用另一种声音的速度冒充目标结果。
5. **比较并放回时间轴**：以逐轮 `measured_delivery_duration` 总和对照 `usable_speech_time`，不得二次扣除交付内成分；再检查句子是否避开必须听清的事件峰值，台词之外是否仍有独立反应与结尾余波。
6. **二次朗读**：改稿后重新测，不沿用旧文本的字 / 秒。
7. **记录状态**：`verified_human_read`、`verified_target_tts` 或 `unverified_estimate` 三选一；只有前两种可称“已实测”。

若当前工作流无法调用真人或目标 TTS：

- 采用保守的起始语速；
- 额外增加非语言余量；
- 明确标记估算风险；
- 不伪造时长、波形、成功率或可懂度结果。

---

## 五、超载时的修复顺序

当 `sum(measured_delivery_duration_per_exchange) > usable_speech_time`，按以下顺序修复：

1. 删除复述画面、背景设定和作者解释。
2. 删除没有信息、关系、行为或权力增量的 exchange。
3. 将能由视线、动作、blocking、物件、环境声或反应表达的内容转回非语言。
4. 每句只保留一个 speech action 和一个必要信息结果。
5. 压缩同义修饰、称呼重复和不影响策略的起手词。
6. 延后非当前戏剧问题必须的信息。
7. 仍超载时按 `delivery_intent` 路由：`single_clip` 标 blocked 并请求删减 / 提时长 / 改 story_complete；`story_complete` 编译连续 Prompt Pack；`auto` 按语义与容量规则判断。
8. 最后才在角色声线允许且实测可懂的范围内加快，绝不直接套 `7–9 字 / 秒` 解决普通对白超载。

把画内对白移成画外音不等于自动获得额外时间。画外音可以与画面动作并行，但仍占发音时间和观众理解带宽；只在它解除口型 / 动作冲突或承担明确声画关系时使用。

## 六、画外音：归属、声画关系与退出点

画外音包括镜外角色说话、画外旁白、上一镜延续的人声和尚未入画主体的提前发声。它必须是某个明确主体或可识别声源的声音。

```text
VoiceoverPlan
  owner: <明确角色或声源>
  mode: <镜外对话 / 旁白 / 上一镜延续 / 提前入声>
  narrative_action: <它正在对观众或角色做什么>
  relationship_to_image: <补充 / 反差 / 误导 / 预告 / 主观化 / 连续>
  voice_print: <词汇、句长、直接程度、节奏、情绪泄漏>
  spatial_relation: <远近、方向、遮挡、空间反射>
  timing: <起止、停顿、与动作或剪点的关系>
  mix_priority: <前景 / 次前景；哪些声音短暂让位>
  exit_point: <何时结束，将注意力交给画面、反应或余波>
```

规则：

- 不写无主旁白；若是全知叙述，也要定义稳定叙述主体与叙事距离。
- 不让画外音朗读画面已经明确表达的动作、身份或情绪。
- 画外音可以先于下一画面形成声音桥，但需写清观众在等待什么信息。
- 重要人声出现时，环境和事件峰值应暂时让位；不要让生成端猜谁必须听清。
- 声音远近和遮挡要与画面空间一致，不能因为“旁白”就失去空间逻辑。
- 画外音应在片段结束前退出，或有意把一个未完成声响作为可续接锚点；禁止无设计地被硬切。

## 七、人声可懂度与声线一致性

台词可念完但听不懂仍然失败。交付前检查：

- 每轮前景信息是否唯一，复杂动作峰值是否避开关键词？
- 发音难度、句法和语速是否适合角色当下的气息与动作？
- 角色在权力转移后，句长、抢话、直接程度或停顿是否出现有动机的变化？
- 口音若被明确要求，是否只作为发音执行条件，而没有替代角色经历、关系、目标和压力？
- 画外音、人声、呼吸、环境和事件音的相对层级是否清楚？
- 重叠时是否明确哪句听清、哪句只作为压力或背景？
- 台词结束后是否仍留出可见反应、收声和最后画面？

## 八、内部预算槽位

```text
总时长：<duration>s
非语言保留：<reserved_nonverbal_time>s，只包含<建立 / 独立动作 / 独立反应 / 环境或声音桥独占节点 / 结尾余波>
可用说话时间：<usable_speech_time>s
语速依据：<verified_human_read / verified_target_tts / unverified_estimate>
首稿字符估算：<drafting_rate_estimate 与 draft_dialogue_chars；仅起草使用>
逐轮完整交付：<speaker + delivery_start/end + measured_delivery_duration，含呼吸 / 句内停顿 / response gap / overlap / interrupt>
交付时长总和：<sum(measured_delivery_duration_per_exchange)>；与<usable_speech_time>比较且不二次扣时
预算结论：<通过 / 需删减 / 需拆分>
最后人声落点：<时间>；片尾剩余<反应 / 动作 / 静默 / 余音>
```

这些字段是内部核算，不要求逐项进入最终提示词。最终只保留会影响生成的台词文本、归属、声线执行、关键停顿 / 重叠 / 打断、混音优先级与结束落点。

## 九、交付前时长检查

- 是否先计算 `duration - reserved_nonverbal_time`，再计算台词预算？
- 叙事视频是否给动作、反应、环境和最后画面留了足够空间，而不是台词占满全程？
- 是否没有把 `7–9 字 / 秒` 当普通快语速？实验性爆发是否极短且经过实测？
- `reserved_nonverbal_time` 是否只含独立非语言节点，没有纳入交付内呼吸、句内停顿、response gap、重叠或打断？
- 是否逐轮实测完整 `measured_delivery_duration`，将其总和与 `usable_speech_time` 比较，且绝未二次扣时？
- 字符 / 语速区间是否只用于起草估算，最终结论是否以完整 delivery 实测为准？
- 是否用真人朗读或目标 TTS 验证；未验证时是否诚实标记 `unverified_estimate`？
- 是否没有用画外音伪造额外理解容量？
- 是否删除了无增量台词，或将其转为动作、反应、声音与静默？
- 最后一句是否在片段结束前自然收住，留出反应、声音余波或稳定最后一帧？
- 人声是否清楚，不被环境、冲击、视效或重叠对白盖住？
