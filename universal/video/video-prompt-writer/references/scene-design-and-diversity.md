# 场景设计与差异化

本文件负责场景自由度、必要的设计决策、候选选择和真实历史去重。场景不是地点名称清单；对生成有用的是主体与空间、材质、光线和行动的关系。

## 1. 从用户目标开始

- 戏剧与行动场景可从叙事功能、路径、遮挡和使用逻辑推导环境。
- 观察、建筑、风格与视觉实验可从构图、尺度、材质、光色或感知关系开始，不必补人物欲望或权力冲突。
- 用户给出完整场景或只要局部编辑时，保留已定设计；不因尚有自由细节而重新生成整套候选。
- 差异应改变实际构图、空间组织、行动路径、光线、材料响应或观看体验。纯粹换名词不构成结构差异；固定风格内的合理复用也不应被判错。

没有指定风格时，从本次观看目标形成可调整的视听方向，不必先归类流派；Agent 自选方向仍属 `free`。专业关系不明或现有方案缺乏有用依据时，按 [创作研究与专业判断](video-element-knowledge-base.md) 查证或探索，再将适用知识落到场景选择，不能用外部案例取代用户故事。

## 2. locked / free

明确来自 brief、指定职责的参考素材或连续性证据的属性标为 `locked`，其他可设计属性为 `free`。内部可记录 `dimension / value / state / source`，不需要把标签输出给用户。

1. locked 进入所有候选，不参与新颖性惩罚。
2. 参考只锁定已声明的职责，外观参考不自动锁死动作或全部空间。
3. 连续性高于去重。禁止为差异化改变地理、方向、光线或状态接点。
4. 不把自己的偏好或模型常见默认误当用户要求；冲突优先按用户最新明确纠偏处理，无法判断且影响交付时再澄清。
5. 渲染必要锚点与选定结果，隐藏来源台账、候选和签名。

## 3. 按需 ScenePlan

这些维度用于解决问题，不要求每个场景全部填写：

| 维度 | 何时使用 | 决策价值 |
|---|---|---|
| `narrative_function` | 戏剧、行动或信息推进 | 空间如何使事件成立 |
| `spatial_topology` | 路径、遮挡、尺度或多层构图重要 | 入口、边界、层级、连通与观察位置 |
| `use_logic` | 物件布局或行动需要空间用途支撑 | 空间为何这样布置，动作如何使用它 |
| `power_geometry` | 人物关系确实通过空间表达 | 谁能进入、观察、占据或退出 |
| `material_family` | 材质是审美或动作控制重点 | 结构、表面、反射、粗糙度和受力响应 |
| `light_source_logic` | 受光、阴影、反射或变化需控制 | 光源方向、光质、作用对象与变化条件 |
| `atmosphere` | 介质影响可见性、光线或事件 | 是否需要空气/天气细节及其作用 |
| `environmental_motion` | 环境参与变化 | 动力、方向、时间与残留 |
| `history_trace` | 使用痕迹承担信息或风格 | 痕迹为何位于那里，不随机做旧 |
| `staging_motif` | 调度或构图关系反复组织注意力 | 距离、方向、层级与重构规则 |
| `continuity_effect` | 多镜头、延长或连续 pack | 需要继承和传递的具体状态 |

简单场景可能只需基线与一项光色选择。专业术语的已知含义不需要在 ScenePlan 或正文重复定义；只有会改变当前设计的条件才展开。

## 4. 候选何时有用

用户要求多方案、明确追求场景差异，或开放任务存在会影响结果的设计分岔时，比较少量候选。通常 2–3 个足够，但没有固定数量门槛。局部修订、已定方案和简单观察可直接成稿。

候选保持相同用户目标及 locked，选择真正可变的关系做比较，不要求至少改变固定数量的维度。内部优先级为：`用户相关性 → 可实现性 → 连续性 → 所需新颖性`。新颖性不能抵消前三项失败。

若候选都被无输入依据的同一默认风格主导，重新检查目标与自由度；不建立新的地点、天气或配色黑名单。最终只交付选中设计，用户要求多方案时才展示候选。

## 5. scene_signature 的唯一约定

只有批量去重、系列管理或用户要求历史比较时才建立签名。保留八个兼容维度；不适用维度标 `not_applicable`，不为了签名虚构人物、用途或天气。

```text
scene_signature
  spatial_topology
  use_logic
  access_and_power
  material_system
  light_logic
  atmosphere
  active_environment
  staging_motif
```

比较同义词归一后的结构值，只比较当前仍为 free 且实际适用的维度。双方的空值、`neutral` 或 `not_applicable` 不当作有意义的相同设计。历史记录必须有真实来源/记录 ID；无历史时不能声称完成历史去重。

`scene_rebuild_threshold` 可由批量配置给定；旧流程的“8 维中 >=5 个相同”仅为待校准初值。可比较维度不足时如实记录证据不足，不擅自改 locked 或降低阈值以制造碰撞/通过结论。

## 6. 碰撞与重建

1. 比较前锁定有证据的连续性，不在碰撞后改标签逃避检查。
2. 对真实已接受历史及本批次已接受结果比较；必要时直接查看内容，避免签名丢失重要区别。
3. 发生实质重复时回到最早重复的 free 决策，改变能影响结果的关系；不通过同义改写或随机换地点伪造差异。
4. 重建后复核用户目标、可实现性、连续性和新签名。
5. 达到调用方 `max_scene_rebuilds` 仍不符合已要求的差异标准时，记录 `needs_review` 或 `rejected`。缺配置且必须据其决策时报告缺项。

可用原因代码：`LOCKED_CONFLICT`、`GENERATABILITY_OVERLOAD`、`CONTINUITY_BREAK`、`SIGNATURE_COLLISION`、`LEXICAL_ONLY_CHANGE`、`TERM_OR_EFFECT_CONFLICT`。代码和历史证据只进入授权的内部审计面，不进入提示词正文。

## 7. 交付前检查

- 场景目标与用户要求一致，locked 未被默认值或新颖性覆盖。
- 只规划适用维度；观察和风格任务没有被改造成强制人物戏剧。
- 候选解决实际设计选择，没有固定数量或差异配额。
- 使用签名时有真实历史，排除了 locked 和不适用维度。
- 选定空间、光色、材质与行动相容；专业条件没有因精简而遗漏。
- 正文保留选中结果，必要跨段锚点可独立使用。
